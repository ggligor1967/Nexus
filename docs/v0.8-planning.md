## 2. Selected scope

A **read-only, structured diff** between a revision's two stored snapshots:

- Computed from the validated `NexusPlan` snapshots already persisted in `revisions.previous_snapshot`
  and `revisions.new_snapshot` (full JSONB; see [database-and-rls.md](database-and-rls.md)).
- Presented **inside the existing** revision snapshot route
  `/projects/[id]/revisions/[revisionId]` (`src/app/projects/[id]/revisions/[revisionId]/page.tsx`),
  which already loads both snapshots under an explicit ownership check + RLS.
- **No new route** unless a later, separately-approved decision adds one.

The diff answers a single user question — *"what changed between these two regenerations?"* — without
mutating anything.

## 3. Rationale

- **Extends v0.7's read-only revision history** rather than reversing any decision.
- **No source-of-truth mutation:** the validated `plan_json` in `ai_plan_runs` is never written by
  this feature.
- **No new write path:** the feature is pure computation over data the user can already `SELECT`.
- **No new RLS policy** and **no migration:** snapshots are already stored and already
  ownership-scoped.
- **Lower risk than restore or PDF:** restore would introduce a source-of-truth mutation and a new
  server-controlled write path (and interacts with SEC-002); PDF would add a runtime dependency and
  a determinism problem. Diff has neither. It is also a natural **stepping stone**: once users can
  see precisely what changed, a future restore scope can be designed more safely.

## 4. Explicit non-scope

The following are **out of scope for v0.8** and must not be implemented under this plan:

- Revision **restore / rollback** (no write path, no source-of-truth mutation).
- **PDF export** (or any new runtime/rendering dependency).
- **Selected prototype marker** / prototype-selection persistence.
- **Diff export / download** (the diff is on-screen only).
- **Field editing, merge, or reordering** of plan content.
- Any change to the **`plan_json` / `NexusPlan` schema** shape.
- **New AI providers** or provider behavior changes.
- **Market scan / market intelligence.**
- **Collaboration / sharing** (multi-user projects).
- **Deployment automation / enterprise CI/CD** expansion.
- **Maintenance items folded into the feature slice** — CI-WARN-001, SEC-001, and DOC-STALE-001 stay
  tracked separately in [maintenance-backlog.md](maintenance-backlog.md); they are not part of this
  v0.8 feature.

## 5. Proposed architecture

**A. Pure diff function**

- New pure function `diffPlans(previous: NexusPlan, next: NexusPlan)`, mirroring the pure,
  deterministic style of `planToMarkdown` (`src/lib/export/markdown.ts`).
- **Deterministic structured output** — identical inputs always produce identical output.
- **String arrays:** report `added` / `removed`, and `unchanged` where it aids readability
  (e.g. `userProblems`, `assumptions`, `misuseCases`, `safeguards`, roadmap phases).
- **Scalar fields:** report `before → after` (e.g. `productThesis`, `strategy.positioning`,
  `ethicalRiskReport.overallRiskLevel`).
- **Grouping** by the plan's top-level sections: product thesis, deconstruction, strategy, prototype
  options, ethical risk, roadmap.
- **Exclude `exportablePlanMarkdown`** from the diff (already excluded from Markdown export).

**B. Presentational component**

- A read-only `DiffView` component that renders the structured diff result.
- Rendered **inline** on `/projects/[id]/revisions/[revisionId]`, alongside the existing
  "Previous version" / "New version" snapshot sections.
- **Reuses the existing ownership/RLS behavior** of that route — no new data fetching, no new access
  path. Non-owners continue to receive `notFound()` (404).

## 6. Security / data model

- **No DB changes** — no new tables, columns, or indexes.
- **No RLS changes** — reuses `revisions` SELECT-own policy + the route's explicit ownership check.
- **No service-role changes** — the admin client is not involved; this feature performs **no writes**.
- **No writes at all** — read + compute + render only.
- **Non-owner access remains 404** (route-level ownership check + RLS, unchanged).
- **Snapshots remain read-only**; the validated `plan_json` in `ai_plan_runs` remains the single
  source of truth.

## 7. Test direction

**`diffPlans` unit tests** (pure, offline — same runner as `tests/e2e/markdown-unit.spec.ts`):

- Deterministic: identical inputs → identical output.
- Scalar changed: `before → after` reported (e.g. `overallRiskLevel` low → critical).
- Array added / removed: items correctly classified.
- No change: identical snapshots produce an empty / "no changes" result.
- `exportablePlanMarkdown` is excluded from the diff output.

**E2E** (fixture mode, local Supabase):

- Generate a standard plan, then regenerate with a surveillance/critical concept.
- Open the revision snapshot at `/projects/[id]/revisions/[revisionId]`.
- Assert the diff section appears.
- Assert a known changed field / risk-level change is shown.
- Assert read-only: no mutation controls (no build-ready control, no restore/edit) are present.
- Assert non-owner access to the snapshot/diff remains **404** (mirror `REV-RLS-001`).
